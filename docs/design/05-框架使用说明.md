## 4. 核心框架使用指南（本项目实际用法）

### 4.1 LLM：openai-agents + LiteLLM（本项目封装）

**不要直接调用 LLM SDK**（Guardrails）。一律走 `LLMBaseModel`：

```python
# 获取模型实例（工厂 + LRU 缓存，maxsize=4；按配置指纹缓存）
model = LLMBaseModel.create_model(agent_config, model_name=None)

# 同步生成
text: str = model.generate(prompt, enable_thinking=False)

# JSON 输出（反思评估等场景）
result: dict = model.generate_with_json_output(prompt)

# 带工具的 Agent 循环（Agentic 节点核心用法，agentic_node.py:1914 真实示例）
result = await self.model.generate_with_tools(
    prompt=summarization_prompt,
    instruction=sys_prompt,        # system prompt
    session=self._session,         # SDK 会话（延续多轮）
    max_turns=1,
    temperature=0.3,
    max_tokens=4000,
    agent_name=self.get_node_name(),
)
summary = result.get("content", "") if isinstance(result, dict) else getattr(result, "content", "") or ""
```

**新增 Provider（已有 SDK 接口）**：只需在 `conf/providers.yml` 加条目（`api_key_env` 指定环境变量名），零 Python 代码。

**新增模型（新 SDK/auth）**：`datus/models/` 下新文件继承 `LLMBaseModel`，实现 `generate*` 系列 + `supports_builtin_web_search` 等能力标记，在 `MODEL_TYPE_MAP`（`base.py:32`）注册。

**理解三路路由**（`litellm_adapter.py`）：官方 OpenAI → `OpenAIResponsesModel`（Responses API）；Claude → `CacheControlLitellmModel`（自动加 ephemeral 缓存断点）；其余 → `LitellmModel`。模型名自动探测/归一化（`MODEL_PREFIX_MAP`）已封装好，业务代码无需关心。DeepSeek/Kimi 的 reasoning 兼容由 `sdk_patches.apply_sdk_patches()` 在入口处打补丁——**不要**在业务代码里做 provider 特判。

### 4.2 语义层与 BI：datus-semantic-core / datus-bi-core

- **消费语义资产**（只读）：检索经 `search_metrics`/`search_reference_sql`/`search_semantic_objects` 等**工具**（Agentic 节点通过工具调用），不直接 import 存储类。手动场景可用 `get_storage(factory, embedding_model, project, datasource_id)`（`storage/registry.py:93`）。
- **管理语义资产**（写）：经 API 端点（`/subject/metric`、`/subject/semantic_model/edit`）或 Subagent（`gen_semantic_model`、`gen_metrics`），YAML 源文件落 `subject/semantic_models/{datasource}/`。
- **BI 集成**：`datus-bi-superset`/`datus-bi-grafana` 为可选包，未安装时 `bi_tools` 不可用；配置在 `agent.services.bi_platforms.<name>`。

### 4.3 数据库：datus-db-core 与 SQL 执行

**不要直接 import 数据库驱动**（Guardrails）。统一经：

```python
from datus.tools.db_tools.db_manager import db_manager_instance

conn = db_manager_instance.get_conn(datasource="demo")   # 懒建连 + 缓存
# 或经工具：execute_sql(sql, datasource=..., database=...) → FuncToolResult
```

- 测试替换点：`set_db_manager_factory(...)`（`db_manager.py:418`）。
- SQL 工具类接口（`func_tool/database.py:1428` 真实形态）：

```python
@mcp_tool()
def execute_sql(self, sql: str, datasource: Optional[str] = "",
                database: Optional[str] = "",
                min_rows: Optional[int] = None, max_rows: Optional[int] = None,
                ) -> FuncToolResult:
    """Execute a single SQL statement against the current database connection.
    ... Google 风格 docstring：概述 + 分类说明 + CAUTION + Args: + Returns:"""
```

### 4.4 向量：LanceDB + FastEmbed

- 索引构建走 Bootstrap（`/build-kb`、`/bootstrap`）或 Skill（`build-kb`），通常不需要手写向量代码。
- 手动检索（只读探索/调试）：`get_storage(...)` 取 `PlainLanceStore`，`search(query, query_type="hybrid")`；混合检索失败自动降级纯向量（`allow_hybrid_fallback`）。
- 嵌入模型默认 all-MiniLM-L6-v2（384 维），文档类 e5-large（1024 维）；配置在 `agent.storage.<domain>.{model_name, dim_size}`；离线可用（`check_snapshot` 先本地后下载）。

### 4.5 Textual TUI 开发约定

- **样式**：所有颜色/符号/辅助函数从 `cli_styles.py` 取（`print_error/print_success/print_warning/print_info/print_status`），禁止 inline Rich 标记。约束：颜色不加 `bold`；`✓`/`✗` 符号；表格 `header_style=TABLE_HEADER_STYLE`，优先 `build_row_table()`；代码 `Syntax()` 用 `CODE_THEME="monokai"`。
- **全屏组件**：参照 `model_app.py` 的 `ModelApp` 模式——`tui_app.suspend_input()` 包裹 `app.run()`；**禁止嵌套 `asyncio.run`**；`DynamicContainer + Condition` 守卫；退出经 `app.exit(result=Selection(...))`。
- 交互选择器导入 `CLR_CURSOR`/`CLR_CURRENT`。

### 4.6 FastAPI + MCP 服务开发

- **新 API 端点**：`datus/api/routes/` 下按领域建路由文件，响应一律 `Result[T]`（`api/models/base_models.py:10`）；流式端点 SSE；用户隔离依赖 `X-Datus-User-Id`（由 `deps.py` 注入 `AppContext`）。
- **新 MCP 工具**：`datus/tools/func_tool/` 下函数 + 装饰器注册（真实形态）：

```python
# 方法级：@mcp_tool(availability_check=...) 按属性控制可见性
@mcp_tool(availability_check="has_schema")
def search_table(self, ...) -> FuncToolResult: ...

# 类级：@mcp_tool_class(name=..., availability_property=...) + 工厂方法
@mcp_tool_class(name="db_tool", availability_property="has_db_tools")
class DBFuncTool:
    permission_category: str = "db_tools"   # 声明权限归属
    @classmethod
    def create_dynamic(cls, ...) / create_static(cls, ...): ...
```

注册后自动进入 MCP Server 与 ToolRegistry——**不需要改 mcp_server.py**。

### 4.7 OpenTelemetry 埋点方式

```python
from datus.observability.manager import get_observability_manager

obs = get_observability_manager()
with obs.span("my_node", {"node": node_id}):      # 上下文管理器
    ...  # 业务逻辑
obs.record_event("my_event", attributes={...})
```

- 内容采集开关：`obs.content_enabled("prompts")` 等按 `capture.*` 配置判断是否上送敏感内容。
- 脱敏：`obs.redact(value)` 自动递归脱敏（敏感字段 → `[REDACTED]`）。
- 自定义 agent 循环（不走 SDK Runner）：用 `trace_native_agent_stream` 装饰器或 `start_native_generation_span/start_native_tool_span/finish_native_span`（`native_agents.py`），注意 async generator 关闭路径已处理，直接复用即可。

## 6. 配置管理（.env、yaml）

| 配置来源 | 内容 | 优先级 |
|---|---|---|
| 环境变量 | Provider key、连接凭据（`${ENV}` 注入） | 值层最高 |
| `-f` 指定文件 | 显式配置 | 最高 |
| `./conf/agent.yml` | 项目内配置 | 次之 |
| `~/.datus/conf/agent.yml` | 全局配置 | 兜底 |
| `./.datus/config.yml` | **仅白名单键**：`target`（provider/model）、`default_datasource`、`project_name`、项目级 `scheduler:`；由 `/model` 等命令写入 | 运行时覆盖 |

**规则**：

- 密钥永不写入 `.datus/config.yml` 与代码；`agent.yml` 中一律 `${ENV_VAR}`。
- 新可调参数放 `agent.yml`（配置节见 DRD-04 §12），不放硬编码常量。
- 多租户只读场景（`config_mutable=False`）：权限提示只提供一次/会话/拒绝，不持久化。

## 7. 日志与 tracing 使用

```python
from datus.utils.loggings import get_logger

logger = get_logger(__name__)
logger.info("node executed", node=node_id, elapsed_ms=...)   # structlog 键值对
logger.error("sql execution failed", error=str(exc), datasource=ds)
```

- 禁止 `print()`；日志经统一配置（`configure_logging`），落 `~/.datus/logs/`。
- 追踪：见 §4.7；本地调试 REPL 内 `Ctrl+O` 切换详细追踪；`--save_llm_trace` 把模型输入输出落盘 `trajectory/`（YAML，含 trace_id），离线复盘用。
- 采集边界：敏感字段（api_key/password/token/secret）在一切导出路径前脱敏——**不要在日志/追踪里打密钥**。

## 8. 常见开发模式与最佳实践

### 8.1 新增 Node（三步）

```python
# 1. datus/agent/node/ 下新建 my_node.py，继承 Node（或 AgenticNode）
class MyNode(Node):
    def setup_input(self, workflow: Workflow) -> Dict:
        self.input = MyInput(sql_task=workflow.task)
        return {"success": True, "message": "ok", "suggestions": [self.input]}

    def update_context(self, workflow: Workflow) -> Dict:
        # 把结果写入 workflow.context（如 sql_contexts）
        return {"success": True, "message": "ok"}

    def execute(self) -> BaseResult:
        self.result = MyResult(success=True, ...)
        return self.result

# 2. datus/configuration/node_type.py 注册 NodeType
# 3. node.py Node.new_instance 工厂加映射
```

参考实现：`date_parser_node.py`（全 110 行，最小完整示例）；输入输出模型在 `schemas/` 建 `my_node_models.py`（Pydantic）。

### 8.2 新增工具函数（一个函数 + 两个装饰器）

```python
@mcp_tool()   # 方法级（类需 @mcp_tool_class 或注册进工具注册表）
def my_tool(self, param: str) -> FuncToolResult:
    """描述用途（Google 风格，docstring 即 MCP 工具描述）"""
```

工具自动进入 MCP Server 与 Agent 工具集；需要权限分类时声明 `permission_category`。

## 9. 调试与常见问题

| 现象 | 排查路径 |
|---|---|
| LLM 行为异常 | `--save_llm_trace` 落盘轨迹 → `trajectory/` 复盘输入输出；确认 `capture.prompts/responses` 已开 |
| 长会话答非所问 | `/compact` 压缩；`/rewind` 回退分支重试；检查上下文 >90% 自动压缩是否误伤细节 |
| 检索不到知识 | `/build-kb` 重建；确认项目隔离（`data/{project_name}/`）；`search_tables` 物化缓存是否过期（`refresh_tables`） |
| SQL 被拒/超限 | `sql_guard` EXPLAIN 估算超 50M 行 → 按 `build_oversize_message` 建议加过滤/分页；`/permission` 调档位 |
| 工具不可见 | 检查 `availability_check/availability_property`（如 `has_db_tools`）；可选包未装（`datus-bi-*`）；DENY 规则把工具从 prompt 隐藏了 |
| 权限行为诡异 | `check_permission` **最后匹配生效**——检查节点级规则是否覆盖全局；同特异性 DENY 优先 |
| 追踪缺失 | `tracing.enabled: true` 才开启（仅设 API key 不生效）；自定义循环用 `native_agents` 系列 |
| SDK 升级后异常 | 三处定点收敛：`sdk_patches.py`、`litellm_adapter.py`、`observability/openai_agents.py`——先回归这三处 |
| 会话回退残留 | `rollback_turn` 已修正 usage 残留；如仍异常检查 session DB 完整性（每会话一个 `.db` 文件） |

## 10. 代码规范与提交约定

**代码规范**（CLAUDE.md）：

- ruff format + check（line-length 120；`extend-exclude = mcp/`；isort stdlib → third-party → `datus.*`）。
- 全量类型提示；数据结构用 Pydantic。
- 英文 only（代码/注释/提交/PR 文本）；中文仅限面向中文用户的文档。
- 日志用 `get_logger`；异常用 `DatusException`；不直接 import DB 驱动；不硬编码 LLM 调用。

**提交前门禁**（按序执行）：

```bash
# 1. 格式化
uv run ruff format datus/ tests/ && uv run ruff check --fix datus/ tests/
# 2. PR 验收 harness（验收 + 受影响单测 + 覆盖率 + diff 覆盖）
uv run python ci/run-pr-tests.py upstream/main
# 3. 测试质量审计（P0=0 门禁；P1 警告应处理）
uv run python ci/audit_tests.py --repo-root . --diff-only upstream/main
# 4. 涉及 CI/验收 harness 变更时：
uv run python ci/run-merge-queue-tests.py
```

**提交约定**：

- 永不 `--no-verify`（pre-commit 钩子自动修复重试）。
- 只 push 到 `origin`，不 push `upstream`。
- 删除代码时同步删/改对应测试；**禁止墓碑测试**（断言"xxx 已不存在"）；外部契约删除例外：加行为级回归测试并注明保护的契约。
- PR 标题前缀：`[BugFix]` `[Enhancement]` `[Feature]` `[Refactor]` `[UT]` `[Doc]` `[Tool]` `[Others]`（CI 拒无类型标题）。
- PR body 用 `.github/PULL_REQUEST_TEMPLATE.md` 三段式（Why / Solution / Test Cases），`gh pr create --body` 以模板为起点。
