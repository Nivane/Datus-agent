## 1. 引言

### 1.1 目的

本文档定义 Datus 智能数据代理（以下简称"系统"或"产品"）的功能需求与非功能需求，作为架构设计（02）、技术方案（03）、详细设计（04）的依据，并为测试与验收提供可追踪、可测试的需求基线。

系统的产品定位：**一个基于 LLM Agent 的智能数据查询与分析系统**，将自然语言转换为准确的 SQL / 语义查询，通过可演化的知识库（语义模型、指标、Reference SQL、平台文档）持续提升查询准确性，并通过 CLI、REST API、MCP、Web Chatbot 四种入口对外提供服务。

### 1.2 范围

**系统边界内（本文档覆盖）：**

- 自然语言查询与 Agent 对话（多轮、流式、计划模式）
- Node 工作流引擎（plan → execute → reflect）
- 语义模型管理与指标查询（Semantic Layer）
- SQL 生成、校验与执行
- 多数据源接入与统一查询
- 向量检索与知识库增强（Knowledge Base / RAG）
- 任务调度与定时分析
- TUI / CLI 交互、REST API 服务、MCP Server / Client
- 结果可视化（报告、仪表盘）与导出
- 可观测性与 Tracing
- 会话与用户隔离

**系统边界外（本文档不覆盖）：**

- LLM 基础模型本身的训练与调优
- 各数据库引擎、Airflow 调度器的内部实现
- 语义适配器背后的 MetricFlow / OSI / Dosi 引擎实现
- 前端业务网站与账户注册体系（系统自身不提供注册/登录）

| Provider | LLM Provider | 大模型提供商（OpenAI、Claude、Gemini、DeepSeek、Qwen 等 10+ 家），经 LiteLLM 统一接入 |
| HITL | Human-in-the-Loop | 人在回路：关键步骤（如计划确认、SQL 执行确认）交由用户确认后继续 |

| OTel / OI | OpenTelemetry / OpenInference | 可观测性标准与 AI 插桩规范 |

## 2. 总体描述

### 2.1 产品前景与目标

数据工程正从"建表与管道"转向"交付面向分析师与业务用户的领域 Agent"。系统的核心主张是：

1. **构建可演化的上下文，而非静态管道**：通过语义模型、Reference SQL、SQL Summary、平台文档构成统一知识层，使 LLM 生成的 SQL 更准确、可信，且随每次交互通过反馈与沉淀持续改进。
2. **从探索到领域 Agent 的完整旅程**：数据工程师先用 CLI 交互式探索数据、构建上下文，领域成熟后封装为 Subagent 交付给分析师（Web/API/MCP）。
3. **度量与改进**：内置 BIRD、Spider 2.0-Snow、Semantic Layer 基准集，量化 SQL 准确率并追踪上下文演化带来的提升。

### 2.2 用户特征

| 用户角色 | 特征 | 典型场景 | 主要入口 |
|---|---|---|---|
| 数据分析师 | 熟悉业务指标与 SQL，不关心内部实现 | 用自然语言问指标与趋势，查看并修正生成 SQL | CLI、Web Chatbot、MCP |
| 业务人员 | 不懂 SQL，只关心业务答案 | 用自然语言直接提问 KPI，无需理解数据模型 | Web Chatbot、Subagent |
| 数据工程师 | 负责数据建模、知识库构建、管道建设 | 定义语义模型/指标、生成 SQL Summary、构建 KB、调度任务、创建 Subagent | CLI（REPL）、API |
| 平台开发者/运维 | 负责部署、接入、二次开发 | 通过 REST API / MCP 将能力嵌入应用，配置 Provider/数据源/可观测性 | API、MCP、配置 |

### 2.3 运行环境

| 项目 | 要求 |
|---|---|
| 操作系统 | Linux 或 macOS |
| Python | 3.12+（安装脚本自动安装到独立 venv `~/.datus/venv`） |
| 网络 | 可访问 LLM Provider API（必须）；可访问外部数据源与 Airflow（按配置） |
| 本地存储 | 默认 `~/.datus/`（可经 `DATUS_HOME` 覆盖）；项目 KB 位于 `{project_root}/subject/` |
| 依赖组件 | LanceDB + FastEmbed（首次构建 KB 时下载嵌入模型，缓存于 `~/.cache/huggingface/fastembed`）；可选包：`datus-bi-superset`、`datus-bi-grafana`、`datus-scheduler-airflow`（未安装时对应能力禁用，核心功能不受影响） |
| 安装方式 | 一行脚本 `install.sh` / `install-dev.sh`（源码）/ `pip install datus-agent` |

### 2.4 约束与假设

**约束（C）：**

- C1 开源约束：产品以 Apache-2.0 开源，不依赖闭源运行时。
- C2 本地优先：配置、会话、知识库默认存于本机 `~/.datus` 与项目 `subject/`、`.datus/`，无内置云同步。
- C3 无内置账户体系：系统不实现注册/登录；用户隔离依赖请求头（`X-Datus-User-Id`）与会话分片。
- C4 多租户只读配置：以 `AgentConfig` 注入配置（`config_mutable=False`）时，Bash/SQL 权限提示只提供"一次/会话/拒绝"选项，不向 `./.datus/config.yml` 写入项目授权。
- C5 密钥管理：凭据仅通过环境变量或 `agent.yml` 的 `${ENV_VAR}` 注入，不入库不落盘明文日志。
- C6 CI 约束：测试环境零 API Key、零预置数据、零网络。
- C7 语言约束：代码与注释英文；面向中文用户的文档可用中文（本文档即属此类）。

**假设（A）：**

- A1 LLM API 可用且具备生成 SQL 的能力（外部依赖）。
- A2 数据源 Schema 可通过 JDBC/驱动或元数据接口获取。
- A3 用户愿意为准确性支付成本：默认工作流带反思节点（reflect），比单次生成消耗更多 token。
- A4 业务指标能够被语义模型结构化表达；无法结构化表达的查询回退到原生 SQL。

### 3.1 F1 自然语言查询与 Agent 对话

#### FR-001 自然语言提问与多轮对话

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | 用户以自然语言提问（如"加州学校平均成绩最高的县"），系统经工作流推理后返回结果与 SQL；支持多轮上下文延续（同一 Session）与流式输出 |
| 输入 | 自然语言文本；可选：Session ID（续接历史）、模型覆盖、语言偏好 |
| 处理 | 1. 会话管理器装载历史消息；2. 进入工作流执行（见 FR-002）；3. 结果经输出节点格式化后流式返回 |
| 输出 | 流式（SSE）或整段 Markdown 回答，含生成 SQL、执行结果、思考过程摘要 |
| 异常 | LLM 调用失败 → 返回错误码并允许重试；SQL 生成失败 → 进入修复链路（FR-021）；执行超时 → 提示并可停止（FR-022） |
| 设计说明 | 多轮能力依赖 Session 持久化（`~/.datus/sessions/{project}/{session_id}.db`）。上下文约 90% 用量时自动触发压缩（`/compact`），避免长会话超出模型上下文窗口——tradeoff：压缩会丢失细节，换取可用性与成本。 |

#### FR-002 Agent 工作流编排

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | 系统以 Node 工作流引擎驱动问答。默认 `reflection` 工作流节点序列为 `schema_linking → gen_sql → execute_sql → reflect → output`；支持并行（parallel）、条件选择（selection）、子工作流（subworkflow）等控制节点 |
| 输入 | 用户消息、会话上下文、知识库检索结果 |
| 处理 | 1. schema_linking 节点从知识库/元数据选出相关表；2. gen_sql 节点生成 SQL；3. execute_sql 节点执行；4. reflect 节点评估结果并决定是否重试；5. output 节点格式化输出 |
| 输出 | 工作流执行结果（回答 + SQL + 轨迹 trace_id） |
| 异常 | 任一节点失败 → 按节点错误处理策略进入修复/终止；reflect 判定不合格 → 自动重入 gen_sql（有限次数） |
| 设计说明 | **核心 tradeoff：结构化工工作流 vs 自由 Agent 循环**。系统选择"可配置节点 DAG + Agentic 节点内自由循环"的混合方案：既有 `reflection` 的自我纠错能力（准确率收益），又保留 `fixed`（无反思、低延迟低成本）、`dynamic`、`chat_agentic`、`metric_to_sql` 等备选工作流，可按场景取舍"准确性 vs 延迟/成本"。节点化使每一步可观测、可替换、可复用于不同领域（Subagent 本质是"定制节点集 + 定制上下文"）。 |

#### FR-003 计划模式（Plan Mode）与执行确认

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | Shift+Tab 进入计划模式：系统先将自然语言任务分解为执行计划，由用户选择执行方式后再实际执行，形成"人在回路"护栏 |
| 输入 | 自然语言任务、可选的计划修订指令 |
| 处理 | 1. 生成计划（任务分解、预期动作）；2. 提供四选：手动确认执行 / 自动执行 / 修订计划 / 取消 |
| 输出 | 计划预览与执行授权结果 |
| 异常 | 计划生成失败 → 提示用户直接提问或重试 |
| 设计说明 | **tradeoff：自主 vs 可控**。默认自由执行保证效率；Plan Mode 与权限提示（`normal/auto/dangerous` 三档配置）把"危险操作（写库、跨库迁移、shell）"纳入人工确认，降低误操作风险。HITL 是产品级设计决策而非后补功能。 |

#### FR-004 会话内消息插入与中断

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | 运行中的对话支持插入新消息（`POST /chat/insert`）与停止（`POST /chat/stop`），CLI 侧可中断进行中的生成/执行 |
| 输入 | 插入消息内容/插入位置；停止指令 |
| 处理 | 运行中的工作流接收中断信号，停止当前节点；插入消息进入消息队列由运行中的 Agent 消费 |
| 输出 | 中断确认 / 插入消息被纳入上下文 |
| 异常 | 中断时 SQL 已执行 → 返回部分结果并标注状态 |
| 设计说明 | 插入能力服务于"边生成边追问"的交互模式；实现上复用流式通道（SSE）双向控制，代价是服务端需要维护运行中任务的句柄与取消传播（见 FR-091 追踪保证取消可观测）。 |

#### FR-005 会话压缩、总结与恢复

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | 支持会话压缩（模型将历史总结为 recap，`/compact` 或上下文 >90% 自动触发）、会话总结落库（`/session-summarize`）、历史会话恢复（`/resume`）与回退分支（`/rewind`） |
| 输入 | 会话 ID、压缩/总结/恢复指令 |
| 处理 | 压缩：用 LLM 生成历史摘要替换旧消息；总结：将会话要点写入持久化存储；恢复：从 sessions 数据库装载历史消息；回退：截断到指定轮次并复制新会话分支 |
| 输出 | 压缩后的会话上下文 / 总结文本 / 恢复后的会话 |
| 异常 | 会话文件缺失或损坏 → 提示重新开始 |
| 设计说明 | 压缩是"上下文窗口有限"约束下的必然 tradeoff：`/compact` 牺牲细节换取长对话可行性；`/rewind` 用分支会话（复制而非覆盖）保留试错轨迹，支持"回退重试"而不丢失历史。 |

#### FR-006 多 Agent / Subagent 选择

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | 系统提供领域化内置 Subagent（`ask_metrics` 指标问答、`explore` 只读探索、`gen_sql` SQL 生成、`gen_report` 报告、`gen_table` 建表、`gen_job` 数据管道、`gen_dashboard` BI 仪表盘、`gen_skill` 技能创建、`scheduler` 调度等），用户或上层应用可指定 Subagent 获得定制上下文与工具集 |
| 输入 | Subagent 标识（API 参数 `subagent_id` / CLI `/subagent` / MCP URL 参数 `?subagent=`） |
| 处理 | 按 Subagent 定义加载其上下文（提示词、知识范围、工具白名单），执行相应工作流 |
| 输出 | 该 Subagent 领域的结果 |
| 异常 | Subagent 不存在 → 明确报错并列出可用列表 |
| 设计说明 | **tradeoff：通用 vs 专业**。通用 Agent 灵活但上下文稀疏；Subagent 用"领域提示词 + 窄化工具集"换取更高准确率与更低 token 成本，代价是每新增领域需维护一套定义。设计上 Subagent 复用同一节点引擎，新增领域 = 配置而非编码。 |

### 3.2 F2 语义模型管理与指标查询

#### FR-010 语义模型定义与存储

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | 支持以 YAML 定义语义模型（维度、度量、指标、实体关系），按数据源分目录持久化于 `subject/semantic_models/{datasource}/`，随项目进入版本管理 |
| 输入 | 语义模型 YAML（人工编写或由 FR-011 生成）、数据源标识 |
| 处理 | 校验（`/semantic_model/validate`）→ 按数据源目录落盘 → 索引进知识库 |
| 输出 | 校验结果与落盘确认 |
| 异常 | YAML 语法/引用错误 → 返回具体校验错误行 |
| 设计说明 | 语义模型"以数据源为单位分目录"的设计使多数据源项目可独立演进语义层；语义模型是知识库的"结构化上下文"，与 Reference SQL 的"半结构化上下文"互补。 |

#### FR-011 语义模型自动生成

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 描述 | 内置 `gen_semantic_model` Subagent 从现有表结构自动生成 MetricFlow 语义模型草稿，`gen_metrics` 生成指标定义，人工审阅后入库 |
| 输入 | 表名/Schema 元数据 |
| 处理 | LLM 依据元数据与语义约定生成 YAML → 校验 → 用户确认 |
| 输出 | 可入库的语义模型/指标 YAML |
| 异常 | 生成结果未通过校验 → 由 Agent 自修复重试 |
| 设计说明 | 自动生成降低语义层建设门槛（数据工程师不必手写 MetricFlow YAML），但生成结果必须人工确认——tradeoff：自动化提速 vs 语义正确性需要领域判断。 |

#### FR-012 指标查询（Metric Query）

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | 支持自然语言指标问答（如"近 30 天 GMV 趋势"）：基于已有语义指标生成指标查询并转译为目标方言 SQL，支撑 KPI、趋势、分组、归因四类问题（`ask_metrics`） |
| 输入 | 自然语言指标问题、指标选择、时间范围 |
| 处理 | 专用 `metric_to_sql` 工作流：`schema_linking → search_metrics（指标检索）→ date_parser（时间表达式解析）→ gen_sql → execute_sql → output` |
| 输出 | 指标结果 + 生成 SQL |
| 异常 | 无匹配指标 → 提示用户改用原生 SQL 或建议新建指标 |
| 设计说明 | **核心 tradeoff：语义层 vs 原生 SQL**。指标查询经语义层保证"口径一致、指标可复用"（业务语言 ↔ 数据库方言的桥），但要求语义模型先建设到位；未覆盖的查询回退原生 SQL。`date_parser` 节点专门把"近 30 天"这类自然语言时间翻译为 SQL 时间条件，是自然语言到 SQL 的关键精度点。 |

#### FR-013 指标定义管理（API）

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 描述 | REST API 提供指标全生命周期管理：`/subject/metric` 创建/编辑/预览/维度列表，`/subject/reference_sql` 创建/编辑，`/subject/semantic_model/edit` 编辑语义模型 |
| 输入 | 指标/Reference SQL 定义、操作类型 |
| 处理 | CRUD + 预览（`metric/preview` 先算后存） |
| 输出 | 操作结果与最新定义 |
| 异常 | 依赖冲突（指标引用不存在的维度）→ 校验错误 |
| 设计说明 | API 化的语义层管理使 Web 前端与自动化工具可复用同一套能力；`preview` 先验证再落库，避免坏定义污染知识库。 |

#### FR-014 语义适配器扩展

| 项 | 内容 |
|---|---|
| 优先级 | P1 |
| 描述 | 语义层通过适配器对接不同语义引擎：MetricFlow / OSI / Dosi，由 `agent.services.semantic_layer` 配置选择 |
| 输入 | 语义引擎类型与连接配置 |
| 处理 | 适配器将统一指标查询翻译为各引擎 DSL，并回填生成 SQL |
| 输出 | 语义查询结果 |
| 异常 | 引擎不可达 → 返回语义层错误并提示回退 |
| 设计说明 | **tradeoff：绑定 MetricFlow vs 多引擎适配**。选 MetricFlow 生态获得成熟语义 DSL 与 YAML 约定；适配层换取不被单一引擎锁定，代价是每新增引擎需维护适配实现（当前支持 MetricFlow/OSI/Dosi）。 |

### 3.3 F3 SQL 生成、校验与执行

#### FR-020 SQL 生成

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | `gen_sql` 节点基于 schema_linking 结果与知识库上下文生成目标方言 SQL；支持专业 Subagent（`gen_sql`）与反思重试 |
| 输入 | 自然语言问题、相关表 Schema、检索到的语义模型/Reference SQL/SQL Summary |
| 处理 | 1. 组装上下文（schema + 知识库命中 + 历史相关 SQL）；2. LLM 生成 SQL；3. 语法校验（SQLGlot）；4. 不合格则进入修复链路 |
| 输出 | SQL 文本 + 生成依据（命中的知识库条目） |
| 异常 | 多次重试仍失败 → 返回失败原因与上下文不足提示 |
| 设计说明 | **准确性的核心 tradeoff：prompt 内上下文 vs 检索上下文**。系统不把全库 schema 塞进 prompt（token 不可行），而是用 schema_linking 选表 + 知识库检索补充——用检索精度换取上下文窗口与成本；SQL Summary 让"同类问题历史成功 SQL"直接参与生成，是准确率提升的主要杠杆（与 Benchmark 联动度量）。 |

#### FR-021 SQL 校验与修复

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | 生成 SQL 经内置校验（语法、方言合规、字段存在性）与质量规则（`datus/validation/` + 校验类 Skill：`sql-modeling-preflight`、`bi-validation`、`table-validation` 等）检查；失败时 `fix` 节点自动修复 |
| 输入 | 待校验 SQL、目标方言、Schema |
| 处理 | SQLGlot 解析 → 校验规则集执行 → 失败项喂回 LLM 修复（有限轮次） |
| 输出 | 通过/失败报告 + 修复后的 SQL |
| 异常 | 校验失败且修复超限 → 终止并给出错误清单 |
| 设计说明 | 校验前移（生成即校验）显著降低"错误 SQL 执行失败"的迭代成本；修复链路把"LLM 自纠"限制在有限轮次内，防止无界重试耗尽 token——tradeoff：修复轮次上限 vs 最终准确率。 |

#### FR-022 SQL 执行与停止

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | 执行生成的 SQL 并返回结果集；支持停止执行（`/api/v1/sql/stop_execute`）；结果可继续用于后续节点（如可视化） |
| 输入 | SQL、数据源标识、执行参数 |
| 处理 | 经数据源适配器（ConnectorRegistry）执行 → 结果集分页/全量返回 → 执行元信息（耗时、行数）回流工作流 |
| 输出 | 结果集（表格式）+ 执行统计 |
| 异常 | SQL 错误 → 携带数据库错误信息进入修复链路；执行超时/资源受限 → 终止并停止 |
| 设计说明 | 统一经数据访问层（`datus-db-core` / ConnectorRegistry）执行而非直连各库驱动——tradeoff：多一层抽象换取方言适配、权限点、追踪点的统一注入点；执行与停止分离保证长查询可中断。 |

#### FR-023 SQL 执行权限控制

| 项 | 内容 |
|---|---|
| 优先级 | P0 |
| 描述 | 危险 SQL（写操作、DDL）执行前需用户确认；提供 `normal / auto / dangerous` 三档权限配置档与 OS 级 Bash 沙箱（`/sandbox`）；多租户只读模式下不持久化授权 |
| 输入 | SQL、当前权限档 |
| 处理 | 按权限档评估：normal 全确认、auto 自动放行读操作、dangerous 全自动；确认结果（一次/会话/永久）按 `config_mutable` 决定是否写入 `./.datus/config.yml` |
| 输出 | 授权结果或确认提示 |
| 异常 | 拒绝执行 → 返回拒绝原因，工作流终止 |
| 设计说明 | 安全与效率的 tradeoff 交由用户按档位权衡；多租户场景（`config_mutable=False`）强制只提供"一次/会话/拒绝"，杜绝跨租户授权泄漏（见约束 C4）。 |

## 4. 非功能需求

### 4.1 性能（NFR-PERF）

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-PERF-01 | 流式首响应 | 对话以 SSE 流式返回，首块（思考过程）应在 LLM 首 token 到达后即时下发，不等待完整生成 |
| NFR-PERF-02 | SQL 执行可中断 | 长查询支持停止（`/stop_execute`），避免工作流被慢查询阻塞 |
| NFR-PERF-03 | 检索延迟 | 知识库检索（向量 + 全文）应支持交互式问答的低延迟（毫秒~百毫秒级），不成为生成链路瓶颈 |
| NFR-PERF-04 | CI 测试速度 | 单测单用例 < 5 秒、确定性（无网络/无 API Key） |
| NFR-PERF-05 | 上下文压缩 | 上下文用量 >90% 自动触发压缩，保证长会话可持续（见 FR-005） |
| NFR-PERF-06 | 成本可控 | LLM token 消耗按工作流类型可预期（`fixed` 低、`reflection` 高），支持按需切换（FR-002） |

### 4.2 准确性（NFR-ACC）

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-ACC-01 | SQL 准确率度量 | 以内置基准（BIRD-DEV、Spider2、Semantic Layer）度量 SQL 准确率，支持通过 Benchmark 框架对比不同配置的准确率差异（如 30 题 19 通过 63%，失败细分 Table/Row Count/Column Value Mismatch） |
| NFR-ACC-02 | 知识库增强 | SQL 生成默认结合知识库检索（semantic models/Reference SQL/SQL Summary），而非纯 Schema 上下文（FR-020） |
| NFR-ACC-03 | 自我纠错 | 默认工作流含 reflect 节点，生成/执行失败自动进入修复链路（有限轮次，FR-002/FR-021） |
| NFR-ACC-04 | 校验前置 | 生成 SQL 经语法与规则校验后才执行（FR-021），降低"错 SQL 污染结果"概率 |
| NFR-ACC-05 | 指标口径一致 | 指标查询强制走语义层（FR-012），保证同一指标多次查询口径一致 |

### 4.3 安全性（NFR-SEC）

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-SEC-01 | SQL 注入防护 | SQL 由模型生成后经语法树解析与规则校验（SQLGlot），不拼接执行用户原串；危险操作（DDL/写操作）需授权（FR-023） |
| NFR-SEC-02 | 密钥管理 | 凭据经环境变量或 `${ENV_VAR}` 注入（约束 C5），不落盘明文、不进入日志与追踪（FR-092 脱敏） |
| NFR-SEC-03 | 执行权限档 | `normal/auto/dangerous` 三档控制确认粒度；OS 级 Bash 沙箱（`/sandbox`）隔离 Shell 执行 |
| NFR-SEC-04 | 多租户隔离 | `config_mutable=False` 时禁止持久化项目授权（约束 C4）；用户经 `X-Datus-User-Id` 隔离（FR-101） |
| NFR-SEC-05 | 工具暴露面 | MCP Server 默认暴露只读 + 检索工具（FR-072）；MCP Client 用过滤器裁剪外部工具（FR-073） |
| NFR-SEC-06 | 供应链 | 技能包支持权限配置与市场（Town Skills Marketplace），安装/发布经 `/skill` 管理 |

## 5. 接口需求

### 5.1 用户接口

- **TUI / CLI（REPL）**：见 FR-060~064 命令体系；退出 `Ctrl+D`/`/exit`；计划模式 `Shift+Tab`；追踪开关 `Ctrl+O`。
- **Web Chatbot（Streamlit）**：`datus-cli --web --datasource demo`，浏览器 `http://localhost:8501`，面向分析师/业务人员。
- **IM 网关**：`datus-gateway` 对接 Slack、飞书，把 Agent 能力带到 IM 场景。

### 5.2 软件接口（REST API v1，前缀 `/api/v1`）

| 类别 | 端点（节选） | 说明 |
|---|---|---|
| 健康检查 | `GET /health`、`GET /docs`、`GET /openapi.json` | 服务可用性 |
| Chat | `POST /chat/stream`（SSE）、`/chat/resume`、`/chat/stop`、`/chat/sessions`、`/chat/sessions/{id}`、`/chat/sessions/{id}/compact`、`/chat/history`、`/chat/insert`、`/chat/user_interaction`、`/chat/feedback`、`/chat/tool_result` | 对话全链路 |
| 知识库 | `POST /kb/bootstrap`、`/kb/bootstrap/{stream_id}/cancel`、`/kb/bootstrap-docs` | SSE 构建进度 |
| MCP 管理 | `/mcp/servers`（CRUD）、`/mcp/servers/{name}/connectivity`、`/mcp/servers/{name}/tools`、`/mcp/servers/{name}/tools/{tool}/call`、`/mcp/servers/{name}/filters` | 外部工具管理 |
| Agent 管理 | `/agent/list`、`/agent/create`、`/agent/edit`、`/agent/delete`、`/agent/tools`、`/agent/use_tools`、`/agent` | Subagent 生命周期 |
| 语义层 | `/subject/list`、`/subject/create`、`/subject/rename`、`/subject/delete`、`/subject/metric`（create/edit/preview/dimensions）、`/subject/reference_sql`、`/subject/semantic_model/edit`、`/semantic_model/validate` | 语义资产管理 |
| SQL 执行 | `POST /sql/execute`、`POST /sql/stop_execute` | 执行与控制 |
| 目录/表 | `/catalog/list`、`/table/detail`、`/table/columns` | 元数据浏览 |
| 仪表盘/报表 | `/dashboard/detail`、`/dashboard/query`、`/report/detail`、`/data_visualization` | 可视化资产 |
| 配置 | `/config/agent`、`/config/datasources`(+`/test`)、`/config/models`(+`/test`) | 运行时配置 |
| 其他 | `POST /auth/token`、`POST /workflows/run`、`POST /workflows/feedback`、`POST /success-stories/insert`、`/models`、`/tools/{tool_name}` | 支撑端点 |

**统一约定**：响应封装 `Result[T]` = `{success, data, errorCode, errorMessage}`；流式端点 `text/event-stream`；用户头 `X-Datus-User-Id`（必填，格式校验）；SQL 策略域头 `X-Datus-Principal`（可选）。

### 5.3 软件接口（MCP）

- **服务端工具**：Database 类（`list_databases`/`list_schemas`/`list_tables`/`search_table`/`describe_table`/`read_query`）、Context Search 类（`list_subject_tree`/`search_metrics`/`get_metrics`/`search_reference_sql`/`get_reference_sql`/`search_semantic_objects`/`search_knowledge`/`get_knowledge`）。
- **服务端模式**：Static（单数据源）/ Dynamic（多数据源，`/mcp/{datasource}`、`/sse/{datasource}`）；传输 http/sse/stdio。
- **客户端**：经 `.mcp.json` 注册外部 Server，`/mcp` 管理（list/add/remove/check/call/filter）。

### 5.4 工作流节点接口

- 节点注册：`node_type.py` 类型注册 + `Node.new_instance()` 工厂映射（NFR-EXT-01）。
- 默认工作流 `reflection`：`schema_linking → gen_sql → execute_sql → reflect → output`；备选 `fixed`、`dynamic`、`empty`、`metric_to_sql`、`chat_agentic`、`gen_sql_agentic`（R5）。
- 工作流选择：配置 `workflow_plan` / `custom_workflows` / CLI `--workflow`。

## 6. 数据需求

### 6.1 数据分类与存储

| 类别 | 存储 | 内容 |
|---|---|---|
| 会话 | `~/.datus/sessions/{project}/{session_id}.db` | 消息历史、压缩摘要、分支 |
| 知识库（向量） | `~/.datus/data/{project}/datus_db/`（LanceDB + Tantivy） | 语义模型、指标、Reference SQL、SQL Summary、平台文档的向量与全文索引 |
| 语义资产（源文件） | `{project_root}/subject/semantic_models/{datasource}/`、`subject/sql_summaries/` | YAML 语义模型、SQL 摘要（随项目版本管理） |

| 全局配置 | `~/.datus/conf/agent.yml`（或 `./conf/agent.yml`、`-f` 指定） | Provider 凭据、服务（数据源/语义层/BI/调度）、模型、可观测性、Benchmark |
| 轨迹 | `{agent.home}/trajectory/` | `--save_llm_trace` 的 YAML 轨迹（含 trace 信息） |

| 基准 | `~/.datus/benchmark/` | BIRD-DEV/Spider2/Semantic Layer 数据集（内置免下载：California Schools） |
| 日志/运行 | `~/.datus/logs/`、`run/`、`workspace/`、`save/` | 日志、运行时数据、工作区、保存产物 |

### 6.2 数据生命周期

- **KB 增量构建**：Bootstrap 支持组件级构建与取消，已构建部分保留可续建（FR-040）。
- **会话保留**：会话按项目分片持久化，支持枚举与删除（FR-102）；压缩生成 recap 摘要替换旧消息（FR-005）。
- **知识沉淀**：查询 → SQL Summary 入库（FR-042）；对话 → `/session-summarize` → 持久化存储 → `/memory-organize` 审计整理。
- **数据隔离**：项目级（`{project_name}` 分片）与用户级（`X-Datus-User-Id`）双层隔离（FR-100/101）。

### 6.3 数据字典（节选）

| 对象 | 关键字段（依据真实代码，节选） |

| Reference SQL | 业务场景、SQL 文本、参数、关联表 |

| Job（调度） | 名称、类型（SQL/SparkSQL）、cron、数据源、SQL 文件、运行状态 |

## 7. 其他需求

### 7.1 安装与升级

- 一键安装（`install.sh`，PyPI 稳定版）与源码安装（`install-dev.sh`，支持分支/标签/commit 钉选，`DATUS_REF`）。
- 可覆盖变量：`DATUS_HOME`、`DATUS_BIN_DIR`、`DATUS_FORCE`、`DATUS_NO_MODIFY_PATH`、`DATUS_VERSION`。
- 运行时升级：`datus upgrade` 升级本体与适配器包。

### 7.2 基准与质量度量

- 内置数据集：BIRD-DEV、Spider2（Spider 2.0-Snow）、Semantic Layer；`benchmark_path` 预配置不可覆盖（防篡改）。
- 运行：`datus-agent benchmark --datasource ... --benchmark bird_dev --benchmark_task_ids <ids>`；评估：`datus-agent eval --benchmark spider2 --output_file evaluation.json`。
- 结果分类：Passed / No SQL / Empty Result / Failed（Table Mismatch、Row Count Mismatch、Column Value Mismatch）；支持自定义 `.csv/.json/.jsonl` 基准与多轮对比。

### 7.3 测试与质量保障

- 三层测试：CI（PR 验收 + 受影响单测，全 Mock、<5s/用例）、Nightly（真实 LLM API）、Regression（真实服务，缺 Key 自动跳过）。
- 测试审计：P0=0 硬性门禁（`ci/audit_tests.py`），禁止"墓碑测试"。
- 覆盖率：Cobertura + diff 覆盖率审查（`ci/run-pr-tests.py`）。

### 7.4 合规与开源

- Apache-2.0 开源许可；无闭源运行时依赖（约束 C1）。
- 文档站点中英双语（MkDocs + i18n，docs.datus.ai）。
